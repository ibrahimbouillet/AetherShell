# Module specification: status_audio (phase A)

Read `AGENTS.md` first; it states the rules every implementer follows. This is the work order that
was given to the implementing engineer. The real headers in the repository are authoritative where
they differ from names used here.

Module: status_audio (directory src/status/audio, target aether_status_audio; deps: aether_core aether_diagnostics aether_platform ole32 plus needed system libs). Do NOT link aether_status: include "status/StatusTypes.h" as a header only.
Your files: src/status/audio/**, tests/unit/status_audio/**, tests/integration/status_audio/**, docs/modules/status_audio.md.
Implement with Windows Core Audio (mmdeviceapi.h, endpointvolume.h, functiondiscoverykeys_devpkey.h):
1. AudioProvider : status::IStatusProvider<status::AudioSnapshot> for the default render endpoint (choose eConsole or eMultimedia and document why). Use IMMDeviceEnumerator, an IMMNotificationClient (OnDefaultDeviceChanged, OnDeviceStateChanged, OnDeviceRemoved), IAudioEndpointVolume and an IAudioEndpointVolumeCallback (OnNotify gives volume and mute). Friendly name from PKEY_Device_FriendlyName. Rebind when the default device changes. No device: state Unavailable, deviceAvailable=false. Audio service unavailable: Unavailable or Error with detail; retry binding on device notifications and otherwise at most every 30 s (bounded).
   Control API used later by the Top Bar: Result<void> SetVolume(float 0..1), SetMuted(bool), ToggleMute(). They execute on the provider's COM thread and return real errors (async with completion, or post and wait with a timeout). Use a per-process event-context GUID so self-initiated changes can be recognized.
2. MicrophoneProvider : status::IStatusProvider<status::MicrophoneSnapshot> for the default capture endpoint (choose the role and document why). Reports deviceAvailable, endpoint mute and endpoint input volume scalar (gain, not a live level). inUseDetection = Support::Unsupported: do NOT infer recording from the existence of an endpoint or from a meter; document that Windows has no documented, reliable cross-version API for "microphone in use". Also expose SetMuted and ToggleMute.
COM threading: Core Audio callbacks arrive on arbitrary threads. Keep all COM objects on a dedicated MTA worker; callbacks only post work to it. Implement the callback interfaces with correct ref counting (winrt::implements works for classic COM interfaces). Unregister callbacks in Stop() before releasing. No listener calls after Stop() returns.
Tests: unit tests for pure snapshot construction, deduplication, volume clamping and fake/stopped-provider controls. Integration tests start both real providers read-only, verify lifecycle, and print only scalar/state diagnostics without device names or arbitrary platform detail strings. Never toggle mute or change output volume/input gain in automated tests. Real control success and notification echo require a later explicitly authorized manual check. This corrects the legacy mute-round-trip permission to match AGENTS.md and PROJECT_SPEC NFR-008; it is not permission to change audio state now.
