# Module specification: accessibility (phase A)

Read `AGENTS.md` first; it states the rules every implementer follows. This is the work order that
was given to the implementing engineer. The real headers in the repository are authoritative where
they differ from names used here.

Module: accessibility (directory src/ui/accessibility, target aether_accessibility; deps: aether_core aether_diagnostics aether_platform uiautomationcore ole32 oleaut32).
Your files: src/ui/accessibility/**, tests/unit/accessibility/**, tests/integration/accessibility/**, docs/modules/accessibility.md.
The Dock, Top Bar and Search surfaces are custom-drawn (Direct2D + Windows.UI.Composition), so they must expose UI Automation themselves. Build a reusable server-side UIA provider for a window that contains a flat list of custom-drawn elements:
- Delegate interface IAccessibleSurfaceModel (implemented later by the UI): RootName(), RootControlType() (for example UIA_ToolBarControlTypeId for the Dock, UIA_PaneControlTypeId), ItemCount(), Item(index) -> AccessibleItem {stable int id, name, helpText, itemStatus (e.g. "Running"), controlType (Button, ListItem, Text, Edit...), screen bounding rect in physical pixels, isEnabled, isFocusable, hasKeyboardFocus, isOffscreen, supportsInvoke, supportsToggle + toggleState}, Invoke(id), Toggle(id), SetFocus(id).
- AccessibleSurface: owns the root provider (IRawElementProviderSimple, IRawElementProviderFragment, IRawElementProviderFragmentRoot) and the item providers (IRawElementProviderSimple, IRawElementProviderFragment, IInvokeProvider, IToggleProvider as applicable). HandleGetObject(hwnd, wParam, lParam, LRESULT&) for WM_GETOBJECT (UiaRootObjectId) via UiaReturnRawElementProvider. Notifications: NotifyStructureChanged() (ChildrenInvalidated), NotifyFocusChanged(id) (UIA_AutomationFocusChangedEventId), NotifyPropertyChanged(id) for name/status, NotifyInvoked(id). Disconnect(): UiaDisconnectProvider for every provider and UiaReturnRawElementProvider(hwnd, 0, 0, nullptr) at WM_DESTROY; providers tolerate calls after the window or model is gone (UIA_E_ELEMENTNOTAVAILABLE). Use ProviderOptions_ServerSideProvider | ProviderOptions_UseComThreading so model access happens on the UI thread. Correct IUnknown ref counting (winrt::implements or hand-written), GetRuntimeId (UiaAppendRuntimeId + id), Navigate (parent, first/last child, next/previous sibling), BoundingRectangle, FragmentRoot, ElementProviderFromPoint, GetFocus, GetEmbeddedFragmentRoots returning null.
Tests: an integration test that creates a real top-level window on the test thread with a model of 3 items and uses the UIA client API (CUIAutomation, IUIAutomation::ElementFromHandle) from a separate MTA thread while the UI thread pumps messages: root name and control type, 3 children with names and control types, bounding rectangles, Invoke on item 2 reaches the model on the UI thread, a focus event is raised, and the element is not available after the window is destroyed. Unit tests for pure helpers (navigation index math, runtime ids).
