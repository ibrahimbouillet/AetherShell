# Module specification: install (phase B)

Read `AGENTS.md` first; it states the rules every implementer follows. This is the work order that
was given to the implementing engineer. The real headers in the repository are authoritative where
they differ from names used here.

Module: install + launcher + updater. Directories: src/install (library aether_install; deps aether_core aether_diagnostics aether_platform aether_updates shell32 ole32 advapi32 user32 bcrypt), launcher/ (executable AetherShell.exe), updater/ (executable AetherShellUpdater.exe).
Your files: src/install/**, launcher/**, updater/**, tests/unit/install/**, tests/integration/install/**, docs/modules/install.md.
THE design to implement: docs/decisions/0005-installation-layout-and-rollback.md. Trust model: docs/decisions/0004-update-trust-model.md; reuse src/updates (manifest parsing, signature verification with the compiled-in trusted keys, SHA-256, SemanticVersion) — never reimplement crypto. The app listens on platform::InstanceChannel name L"AetherShell" and accepts the command L"shutdown-for-update"; the app accepts "--post-update-check <hex token, 16..64 chars>" (src/app/CommandLine.h). The app binary inside a version folder is AetherShellApp.exe (built by the lead from src/app).
Library (unit-testable: inject roots, registry roots, process operations and clocks via small interfaces; tests never touch real install locations or processes):
1. InstallLayout: all paths of ADR 0005 from an install root; every path must stay inside the root (aether::fs::IsPathWithin); version folder names validated as SemVer.
2. InstallState journal: schema v1 JSON {schemaVersion, product "AetherShell", activeVersion, previousVersion, transaction?{id, fromVersion, toVersion, state, healthToken?, startedUtc, updatedUtc, error?}}; states Prepared, Verified, Staged, Applying, Installed, HealthCheckPending, Committed, RollbackRequired, RolledBack; strict parsing; atomic saves; reject illegal transitions.
3. PayloadManifest + PayloadReader: the setup executable embeds RCDATA "PAYLOAD_MANIFEST" (JSON v1 {schemaVersion, product, version, architecture, files:[{name, resource, size, sha256}]}) plus one RCDATA per file. Read with LoadLibraryExW(LOAD_LIBRARY_AS_DATAFILE_EXCLUSIVE | LOAD_LIBRARY_AS_IMAGE_RESOURCE) — never execute it. Names: plain or simple relative paths, no "..", drive, ":" or reserved device names; <= 64 files; <= 512 MB total. Extract into staging verifying each size and SHA-256; any mismatch deletes the staging folder.
4. Operations: StageVersion, ActivateVersion (atomic rename staging->versions + state switch), CommitUpdate (delete versions older than previous; never active or previous), Rollback, RecoverInterrupted (ADR 0005 rules), CleanupStaging, disk-space check.
5. Health protocol: token = 32 hex chars from BCryptGenRandom; manual-reset named event "Local\AetherShell.Health.<token>" created by the updater; SignalHealthy(token) for the app (export this function in a small header the app can include); WaitForHealthy(token, timeout).
6. ProcessCoordinator: request exit through InstanceChannel::Send(L"AetherShell", L"shutdown-for-update"), wait for the listener process (FindListenerProcessId + OpenProcess(SYNCHRONIZE)) with a 30 s timeout; never terminate a healthy app. Only during rollback may a version that failed its health check and ignores the exit request for 15 s be terminated, because the updater launched it itself (document).
7. Helpers for the installer: Start Menu shortcut (IShellLinkW, FOLDERID_Programs\Aether Shell.lnk -> launcher, description, icon), optional desktop shortcut, uninstall registration under HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\AetherShell (DisplayName "Aether Shell", DisplayVersion, Publisher "Ibrahim Bouillet", InstallLocation, DisplayIcon, UninstallString ""<root>\AetherShellSetup.exe" --uninstall", ModifyPath "... --repair", EstimatedSize, URLInfoAbout https://github.com/ibrahimbouillet/AetherShell) and removal; registry roots injectable (tests use HKCU\Software\AetherShellTests\...). The Run key belongs to src/settings StartupRegistration — call it, do not duplicate.
Launcher (launcher/main.cpp -> AetherShell.exe, WIN32, tiny): read install-state.json next to itself, RecoverInterrupted(), start versions\<active>\AetherShellApp.exe with its own arguments (CreateProcessW with a command line built only from its argv elements via a correct argv-quoting routine; working directory = the version folder), then exit. Missing/corrupt state: clear MessageBox suggesting Repair from Settings > Apps > Installed apps; non-zero exit.
Updater (updater/main.cpp -> AetherShellUpdater.exe, WIN32): --apply --package <setup.exe> --manifest <manifest.json> --signature <manifest.json.sig> --install-root <dir> [--data-dir <dir>] [--wait-pid <pid>]. Follow ADR 0005 exactly: Prepared -> independent re-verification (signature, size, SHA-256, architecture, minimum OS) -> Verified -> disk space -> Staged -> request exit + wait -> Applying -> activate -> Installed -> start the launcher with --post-update-check <token> -> HealthCheckPending -> wait (90 s) -> Committed, or RollbackRequired -> rollback -> RolledBack -> restart previous. Write <dataRoot>\updates\last-update-result.json {version, outcome, error, timeUtc} for the app (dataRoot default %LOCALAPPDATA%\AetherShell). Small native progress window (progress bar + status). Log to <dataRoot>\logs\updater.log.
If resources/branding/ico/AetherShell.ico exists, embed it as the executables' icon (IDI_APP = 1) through a small .rc in your folders; otherwise note it.
Tests: unit — layout containment, state parse/validate/transitions, payload manifest validation (traversal, duplicates, limits, reserved names), RecoverInterrupted for every state, CommitUpdate never deleting active/previous, health token format, argv quoting (quotes, trailing backslashes, spaces), registry helpers on the test key (cleaned up). Integration — build a small test executable with RCDATA payload (manifest + 2 files) via a test .rc, then StageVersion/ActivateVersion/RecoverInterrupted/Rollback end-to-end in a temp install root, plus health-check success and timeout with no real app.
