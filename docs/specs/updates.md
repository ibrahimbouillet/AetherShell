# Module specification: updates (phase A)

Read `AGENTS.md` first; it states the rules every implementer follows. This is the work order that
was given to the implementing engineer. The real headers in the repository are authoritative where
they differ from names used here.

Module: updates (directory src/updates, target aether_updates; deps: aether_core aether_diagnostics aether_platform bcrypt crypt32 wintrust). Do NOT link aether_net: use aether::net::IHttpClient (src/core/Http.h); the WinHTTP client is written in parallel and injected by the application.
Your files: src/updates/**, tests/unit/updates/**, scripts/release/**, docs/modules/updates.md, docs/decisions/0004-update-trust-model.md.
Model: official public GitHub repository (owner and name from aether/BuildInfo.h: kUpdateRepositoryOwner "ibrahimbouillet", kUpdateRepositoryName "AetherShell") -> release metadata -> signed manifest -> verified asset download -> staged package. Installing the package is done later by a separate updater executable, not by this module.
1. SemanticVersion: full SemVer 2.0.0 parse and compare (numeric identifiers without leading zeros, numeric versus alphanumeric prerelease precedence, build metadata ignored for precedence; reject malformed input: leading zeros, empty identifiers, invalid characters, missing parts, overflow). Tag normalization accepts exactly one leading "v" or "V" (documented rule). ToString. Exhaustive tests, including the SemVer spec chain 1.0.0-alpha < 1.0.0-alpha.1 < 1.0.0-alpha.beta < 1.0.0-beta < 1.0.0-beta.2 < 1.0.0-beta.11 < 1.0.0-rc.1 < 1.0.0, and 1.10.0 > 1.9.0.
2. GitHubReleaseClient: GET https://api.github.com/repos/{owner}/{repo}/releases/latest for the stable channel, or /releases?per_page=30 for the prerelease channel (newest non-draft release by SemVer precedence among valid tags, prereleases included). Headers: Accept: application/vnd.github+json, X-GitHub-Api-Version: 2022-11-28, User-Agent. Conditional requests with If-None-Match/ETag from a metadata cache (304 uses the cache). Never send a token. Parse strictly into ReleaseInfo {tagName, version, name, body (untrusted text, cap 64 KB), htmlUrl (must start with https://github.com/{owner}/{repo}/), prerelease, draft, publishedAt, assets [{id, name, size, contentType, browserDownloadUrl (must start with https://github.com/{owner}/{repo}/releases/download/)}]}. Ignore drafts. 404: NotFound ("no releases published yet"). 403 or 429 with x-ratelimit-remaining: 0 or retry-after: RateLimited with the reset time (x-ratelimit-reset epoch). 5xx: Unavailable. Response size limit 2 MB. Redirect allow-list: api.github.com only.
3. Asset naming and manifest. Assets: AetherShell-<version>-win-<arch>-setup.exe, AetherShell-<version>-manifest.json, AetherShell-<version>-manifest.json.sig, AetherShell-<version>-checksums.txt. Manifest schema v1: {"schemaVersion":1,"product":"AetherShell","version":"<semver>","channel":"stable|prerelease","minimumWindowsBuild":19041,"releaseNotesUrl":"https://github.com/...","assets":[{"filename":"...","architecture":"x64|arm64","format":"exe","sha256":"<64 lowercase hex>","size":<bytes>}]}. UpdateManifest::Parse validates strictly: exact product; version equals the release tag version; channel consistent with the prerelease flag; sha256 is 64 hex characters and not a placeholder (all zeros, "<release-generated-digest>" and similar); size > 0 and <= 512 MB; filename follows the convention and contains no path separators or ".."; known architectures; no duplicate filenames. SelectAsset(arch, osBuild): wrong architecture or OS build below the minimum gives an Unsupported error.
4. Trust model (write docs/decisions/0004-update-trust-model.md): integrity (SHA-256 of the downloaded asset versus the manifest) is separate from authenticity (ECDSA P-256/SHA-256 signature over the exact manifest bytes, verified against a public key compiled into the application). A checksum alone never proves who published an asset. Implement with Windows CNG (bcrypt.h): Sha256 (incremental hasher plus one-shot); EcdsaP256Verifier (BCRYPT_ECDSA_P256_ALGORITHM, BCRYPT_ECCPUBLIC_BLOB with BCRYPT_ECDSA_PUBLIC_P256_MAGIC); the .sig asset holds a base64 64-byte r||s (IEEE P1363) signature; also accept DER-encoded ECDSA signatures through a strict minimal DER parser. Strict base64 decoding (CryptStringToBinaryA or your own strict decoder). TrustedKeys.h holds the production release key (P-256 public key, uncompressed point X||Y in hex):
   2b0310c62dd1d8ec4e6b16c9caf44fced9f8df43f3807bc9d3e425ca28f4e12f66b5ed190dad7d96f79405a82e7f5e60e5caa622a379bc19edfb42c92cb0ce02
   Its private key is held offline by the project owner; you do not have it. Support a list of trusted keys (rotation). Tests construct verifiers with their own test key through the constructor; the production path uses only TrustedKeys. Also implement an optional Authenticode check (WinVerifyTrust, WINTRUST_ACTION_GENERIC_VERIFY_V2, no UI, whole-chain revocation) behind a policy enum NotRequired | RequiredIfPresent | Required, default NotRequired because the project has no code-signing certificate yet; document this honestly.
   For tests: generate a TEST key pair with OpenSSL in a temporary directory, sign test manifests, and embed the test public key and signatures in the test source. Never commit a private key (*.pem is git-ignored).
5. UpdateDownloader: download the selected asset with IHttpClient::SendStreaming to <updatesDir>/downloads/<version>/<filename>.partial, hashing while streaming; enforce the exact expected size (abort when exceeded); check free disk space first (size * 3 + 50 MB, else ErrorCode::InsufficientSpace; make the disk-space query injectable); redirect allow-list github.com, objects.githubusercontent.com, release-assets.githubusercontent.com; bounded retries (3 with backoff, restarting from zero); cancellation; progress callback. On success verify size and digest, then rename atomically to the final name; on mismatch delete the partial file and return ErrorCode::Integrity. The final path must be inside the downloads directory (aether::fs::IsPathWithin). Never execute anything.
6. UpdateCoordinator: check -> manifest and signature download + verification -> compatibility -> (on user request) asset download + verification -> ReadyToInstall {package path, manifest path, signature path, version}. States: Disabled, Idle, Checking, UpToDate, UpdateAvailable (with ReleaseInfo, manifest, sanitized notes, download size), Downloading (progress), ReadyToInstall, Error (Error + retryable + optional retry-after). API: StartAutomaticChecks(UpdatePolicy{enabled, interval, channel, skippedVersion}), CheckNow(), DownloadAndPrepare(), SkipVersion(version), Postpone(), Cancel(), Snapshot(), Subscribe(listener) delivered through IUiDispatcher (UI thread). Scheduling: first automatic check 2 minutes after start, then every interval (min 6 h, default 24 h) based on lastCheck persisted in a state file (<configDir>/update-state.json: lastCheckUtc, etag, cached release metadata, skippedVersion); bounded backoff on failures (15 min, 1 h, 4 h, then the interval). Network work on a WorkerPool; time through ITimeSource and an injectable timer abstraction so tests can drive scheduling. Offline or rate-limited: Error with retryable=true. Current version from aether::build::kVersion (injectable for tests).
7. Release notes are untrusted: provide a sanitizer that converts the release body to safe plain text (strip control characters except newline and tab, normalize CRLF, cap length, collapse runs of blank lines). The UI renders plain text only.
8. scripts/release/ (Python 3.11+ standard library only): make_manifest.py (version, channel, asset files -> manifest JSON with real sha256 and size; refuses placeholders), sign_manifest.py (runs the openssl CLI "dgst -sha256 -sign <key>" to get DER, converts to base64 P1363, then verifies with the public key; key path from an argument or the AETHER_RELEASE_SIGNING_KEY_FILE environment variable; never prints key material), make_checksums.py (sha256sum-compatible lines).
Tests (unit; fakes for IHttpClient, ITimeSource, timer and dispatcher): no update available; newer update; invalid tags skipped; API unavailable (5xx and transport); rate limit (403 with remaining 0, 429 with retry-after); 304 cached; interrupted download (sink error mid-way); corrupted download (digest mismatch); size exceeded; manifest/tag mismatch; wrong architecture; unsupported Windows build; invalid signature (tampered byte, wrong key, malformed base64 and DER); insufficient disk space; drafts ignored; prerelease channel selection; skipped version not announced; untrusted redirect hosts not allowed (check request.allowedRedirectHosts and a fake that reports a redirect error); cancellation; scheduler timing.
