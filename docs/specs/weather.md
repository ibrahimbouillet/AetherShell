# Module specification: weather (phase A)

Read `AGENTS.md` first; it states the rules every implementer follows. This is the work order that
was given to the implementing engineer. The real headers in the repository are authoritative where
they differ from names used here.

Module: weather (directory src/weather, target aether_weather; deps: aether_core aether_diagnostics aether_platform). Include "status/StatusTypes.h" as a header only; do NOT link aether_status or aether_net. HTTP goes through aether::net::IHttpClient (src/core/Http.h); the WinHTTP implementation is being written in parallel and will be injected by the application.
Your files: src/weather/**, tests/unit/weather/**, docs/modules/weather.md.
Provider: Open-Meteo (no API key, HTTPS). Verify the current API with WebFetch (https://open-meteo.com/en/docs and https://open-meteo.com/en/docs/geocoding-api and the licence/terms page) before coding. Forecast request: https://api.open-meteo.com/v1/forecast?latitude=..&longitude=..&current=temperature_2m,weather_code,is_day&temperature_unit=celsius|fahrenheit&timezone=auto . Geocoding: https://geocoding-api.open-meteo.com/v1/search?name=<encoded>&count=5&language=<lang>&format=json . Every Available or Cached snapshot carries the attribution "Weather data by Open-Meteo.com". Percent-encode user-provided text as UTF-8; never splice raw text into URLs. Format coordinates with a fixed number of decimals and the invariant "." separator.
Design:
1. WeatherProvider : status::IStatusProvider<status::WeatherSnapshot>, constructed with IHttpClient&, ITimeSource&, the cache file path and a WeatherConfig {enabled, latitude?, longitude?, locationName, unit, refreshInterval}. UpdateConfig(config) applies new settings and refetches when the location or unit changes. Disabled: state Disabled and no network traffic at all. Enabled without coordinates: LocationNotConfigured, no traffic.
2. Fetch on a WorkerPool thread with timeouts (connect 10 s, receive 15 s), cancellation on Stop/UpdateConfig (CancellationSource), and a bounded retry with backoff (for example 3 attempts at 30 s, 2 min, 10 min) before waiting for the next scheduled refresh. Refresh every refreshInterval (default 30 min) with a timer, never a busy loop. RefreshNow() is rate-limited to once per 60 s.
3. Strict response parsing with aether::json: check types and ranges (temperature plausible for the unit, weather_code 0..99), response size limit 256 KB, provider error JSON ({"error":true,"reason":...}). HTTP 429 or 5xx: ProviderUnavailable. Network or timeout errors: Offline when there is no usable cache, otherwise Cached with the cached data and its observedAt/fetchedAt.
4. Cache: persist the last good result as JSON (location key, unit, temperature, code, is_day, observedAt, fetchedAt) atomically with aether::fs::WriteFileAtomic; load it at Start. Cached data older than 6 h is not shown. Never present cached data as fresh: Available only after a successful fetch in this session within the refresh interval.
5. WMO weather code to English condition text (0 Clear sky, 1 Mainly clear, 2 Partly cloudy, 3 Overcast, 45/48 Fog, 51-57 Drizzle, 61-67 Rain, 71-77 Snow, 80-82 Rain showers, 85-86 Snow showers, 95-99 Thunderstorm) and a glyph category enum (Clear, PartlyCloudy, Cloudy, Fog, Drizzle, Rain, Snow, Thunder, Unknown) plus is_day, exposed for the Top Bar renderer (add them to your own header, for example WeatherConditions.h).
6. GeocodingClient::Search(query, languageTag, cancel) returns vector<LocationCandidate{name, admin1, country, latitude, longitude}> for the Settings UI (blocking; call on a worker thread).
Tests (unit, with a FakeHttpClient implementing IHttpClient and aether::FakeTimeSource): disabled sends no requests; not configured; success; malformed JSON; out-of-range values; HTTP 500 and 429; timeout error gives Offline; failure with a fresh cache gives Cached; stale cache ignored; unit switch refetches; URL encoding of non-ASCII names; retry bound respected; no listener calls after Stop. No network tests are required.
